<h2>v1.5.2 - Regalia Slots API &amp; Config Folder Fix</h2>

<h3>Change</h3>
<ul>
<li><strong>Curios dependency replaced with Regalia Slots API</strong>: the team now maintains its own fork of Curios (<code>regalia_slots_api</code>, LGPL-3.0), so the mod's required dependency for wearable EMC items (Klein Stars, rings, amulets, stones, talisman, watch) changes from <code>curios</code> to <code>regalia_slots_api</code>.</li>
</ul>
<blockquote><strong>Breaking for existing installs</strong>: anyone running Curios alongside Equivalent Legacy must replace it with Regalia Slots API — the mod no longer recognizes Curios as a slot provider.</blockquote>

<h3>Fix</h3>
<ul>
<li><strong>Config folder used the wrong name</strong>: <code>EquivalentLegacyConfig</code> registered <code>server.toml</code>/<code>common.toml</code>/<code>client.toml</code> (and the <code>CustomEMCParser</code>/<code>EMCMappingHandler</code> files: <code>custom_emc.json</code>, <code>mapping_dump.json</code>, <code>pregenerated_emc.json</code>) under <code>config/EquivalentLegacy/</code>, using the PascalCase display name instead of the snake_case mod id. Fixed so the folder is <code>config/equivalent_legacy/</code>, consistent with the rest of the mods.</li>
</ul>
<blockquote><strong>Breaking for existing installs</strong>: any world or server with the mod already installed had its configuration under <code>config/EquivalentLegacy/</code>. After updating, the mod looks for (and regenerates with defaults) <code>config/equivalent_legacy/</code> — the old folder is <strong>not</strong> deleted or migrated automatically. Anyone with custom configuration (server.toml, custom_emc.json, etc.) must manually copy the contents of <code>config/EquivalentLegacy/</code> to <code>config/equivalent_legacy/</code> before starting, or reapply the changes by hand.</blockquote>
