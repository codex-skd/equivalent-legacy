<h2>v1.6.4 - Repair Talisman actually repairs items in Regalia Slots API slots</h2>

<p>1.6.3's changelog claimed this was fixed, but that release only added items to <code>curios:*</code> tags &mdash; <code>RepairTalisman.java</code> was never touched, and damaged items sitting in a Regalia slot were still not repaired.</p>

<h3>Fix</h3>
<ul>
<li><strong>Repair Talisman did not repair items equipped in Regalia Slots API slots</strong>. The talisman already iterated the Regalia slots through <code>IntegrationHelper.getCurioItemHandler</code>, but that handler is NeoForge's legacy <code>IItemHandler.of(ResourceHandler)</code> bridge (<code>ItemResourceHandlerAdapter</code>), which is not <code>IItemHandlerModifiable</code> and whose <code>getStackInSlot</code> returns a fresh <code>ItemStack</code> copy every call. So <code>RepairTalisman.repairAllItems</code> fell to its <code>else</code> branch and called <code>setDamageValue</code> on a throwaway copy &mdash; a no-op. When the handler is not modifiable, the repair is now applied through <code>extractItem</code> + <code>insertItem</code> (which mutate the backing handler transactionally), guarded by an <code>isItemValid</code> check so the item is guaranteed to return to its slot with no risk of loss.</li>
</ul>
