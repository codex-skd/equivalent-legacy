<h2>v1.2.0-beta.10 - Asset Namespace Migration Fix</h2>

<h3>Fixed</h3>
<ul>
<li><strong>Critical: Texture/Icon Loading</strong>: All 297+ asset references corrected from <code>projecte:</code> namespace to <code>equivalent_legacy:</code> namespace. This was preventing item icons and block textures from loading in-game.</li>
<li><strong>Asset Structure</strong>: Removed duplicate <code>items/</code> directory (106 files) that was causing confusion; all item models are now correctly located in <code>models/item/</code></li>
<li><strong>Blockstate Validation</strong>: Fixed 3 malformed blockstate JSON files with missing closing braces</li>
</ul>

<h3>Changes</h3>
<ul>
<li>297 files modified: blockstates (23), models/item (278), sounds.json (1), and models/block (28)</li>
<li>106 files removed: duplicate items/ directory</li>
<li>All asset JSON files validated and verified to parse correctly</li>
<li>All texture and model references now resolve to existing files</li>
</ul>

<h3>Technical Details</h3>
<ul>
<li><strong>Root Cause</strong>: Incomplete migration from Equivox/ProjectE fork — asset JSON files still referenced the old <code>projecte:</code> namespace instead of the mod's identifier <code>equivalent_legacy:</code></li>
<li><strong>Impact</strong>: Minecraft client was unable to find models and textures, resulting in missing icons in inventory and missing block/item visuals</li>
<li><strong>Resolution</strong>: Namespace migration via mass sed replacement + validation of all 335 asset JSON files</li>
</ul>
