<h2>v1.5.0 - Enchantable Equipment &amp; Break-Drop Fix</h2>

<h3>Feature</h3>
<ul>
<li><strong>PE swords, tools and armor can now be enchanted</strong>: <code>PESword</code>, <code>PETool</code> (pickaxe/axe/shovel/hoe), <code>PEShears</code> and <code>PEArmor</code> previously hardcoded <code>isPrimaryItemFor</code>/<code>supportsEnchantment</code> to <code>false</code> (matching the upstream ProjectE 1.21.1 reference), blocking vanilla enchanting entirely. Those blocks have been removed so the standard <code>minecraft:enchantable/*</code> tag rules apply, and each matter tier now carries a proper enchantment value (Dark Matter 18, Red Matter 22, Gem armor 24). The dm_/rm_/gem_ equipment set was also explicitly excluded from those tags via <code>"remove"</code> — added back. The charge/EMC system is unaffected; both bonuses stack independently.</li>
</ul>

<h3>Fix</h3>
<ul>
<li><strong>Collector/Pedestal/Matter Furnace still lost their inventory on break (the 1.4.3 fix didn't actually work)</strong>: <code>Block#onBlockStateChange</code> fires from <code>Level#markAndNotifyBlock</code>, which runs <em>after</em> <code>LevelChunk#setBlockState</code> has already removed the block entity from the level — any inventory drop attempted from that hook looks up an already-missing block entity and silently loses its contents. This is why the Collector fix shipped in 1.4.3 never actually worked in practice. Inventory drops now happen from <code>BlockEntity#preRemoveSideEffects</code> instead, which runs right before the block entity is removed: Collector (input+aux), Pedestal (held item) and Matter Furnace (input/output/fuel).</li>
</ul>
